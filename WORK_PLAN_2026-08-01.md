# Piano di Sessione: Multi-PDF — Replace & Tab

**Data pianificazione:** 2026-08-01
**Feature:** Caricare un nuovo PDF mentre un altro è già in visualizzazione
**Branch:** `main`

---

## 1. Obiettivo

Oggi l'app supporta **un solo PDF alla volta**. Quando un PDF è aperto, l'utente deve:
- Andare nel drawer → "Open PDF" → selezionare un file → il PDF corrente viene sostituito

L'obiettivo è rendere più fluido il caricamento di un nuovo PDF e, opzionalmente, permettere di tenere **più PDF aperti contemporaneamente** in una struttura a tab.

---

## 2. Due livelli di implementazione

### Livello 1 — Replace migliorato (quick win, ~1h)

Il PDF corrente viene **chiuso e sostituito** dal nuovo. L'architettura attuale (`usePDFLoader` singleton) già lo supporta. Miglioramenti UX:

| Cosa | Stato attuale | Miglioramento |
|---|---|---|
| Drag & drop su viewer | ❌ Non possibile | ✅ Drop su viewer → sostituisce PDF corrente |
| Bottone "Open" | Seppellito nel drawer | ✅ Bottone visibile nella TopBar (già c'è, solo visibilità condizionale) |
| Scorciatoia tastiera | ❌ | ✅ `Ctrl+O` / `Cmd+O` |
| Conferma se PDF modificato | ❌ | ✅ Dialog "Hai modifiche non salvate. Continuare?" |

**Architettura:** Nessuna modifica strutturale. Solo UI.

### Livello 2 — Tabs (strutturale, ~3-4h)

PDF multipli aperti come tabs, tipo browser o VS Code.

```
┌──────────────────────────────────────────────────┐
│ [📄 doc1.pdf] [📄 report.pdf] [📄 invoice.pdf] [+] │  ← Tab bar
├──────────────────────────────────────────────────┤
│                                                  │
│              Viewer del tab attivo               │
│                                                  │
└──────────────────────────────────────────────────┘
```

---

## 3. Architettura attuale (analisi)

```
App.tsx
  ├── usePDFLoader()     → stato SINGLE pdf, pdfBytes, numPages, fileName, ...
  ├── usePageSelection() → selezione pagine
  ├── useReorder()       → riordino
  ├── hasPDF = pdf !== null
  │
  ├── hasPDF === false → <PDFUploader />
  └── hasPDF === true  → <UnifiedViewer pdf={pdf!} numPages={numPages} ... />
```

**Punto critico:** `hasPDF` è un booleano. Per i tabs diventa `activeTabIndex !== null` o simile.

---

## 4. Decisioni da prendere

### 🔴 D1: Approccio — Replace-only o Replace+Tabs?

| | Replace-only | Tabs |
|---|---|---|
| Complessità | Bassa | Alta |
| Tempo | ~1h | ~3-4h |
| Vantaggio | Subito disponibile | Multi-documento potente |
| Rischio | Sottoutilizzo se poi si vuole tabs | Overengineering se mai usato |

**Raccomandazione:** Fare **entrambi in sequenza**. Prima Replace migliorato (subito usabile), poi Tabs (fase 2).

### 🟡 D2: Dove mettere la Tab Bar?

| Posizione | Pro | Contro |
|---|---|---|
| **Sopra la TopBar** | Naturale, spazio abbondante | Aggiunge altezza |
| **Dentro la TopBar** (sostituisce titolo) | Compatta | Poco spazio su mobile |
| **Sotto la TopBar** | Visibile, separata | Consuma spazio verticale |

**Raccomandazione:** Dentro/sotto la TopBar su desktop, drawer o bottom sheet su mobile.

### 🟡 D3: Stato per-tab — cosa isolare?

Ogni tab deve avere il proprio stato indipendente:

| Stato | Isolato per tab? | Note |
|---|---|---|
| `pdf` / `pdfBytes` / `numPages` | ✅ Sì | Core |
| `fileName` | ✅ Sì | |
| `selectedPages` | ✅ Sì | Selezione indipendente |
| `currentPage` / scroll | ✅ Sì | Ripristina posizione al tab switch |
| `rotation` | ✅ Sì | |
| `pagesPerRow` / `zoom` / `fitMode` | ❓ Globale o per-tab? | Probabilmente globale (preferenza utente) |
| `isModified` / `originalPdfBytes` | ✅ Sì | |
| `cachedTOCItems` | ✅ Sì | |

### 🟡 D4: Gestione memoria — mantenere tutti i PDF in memoria?

Con 5 tab aperti, ogni PDF da 50MB → 250MB RAM.

| Strategia | Pro | Contro |
|---|---|---|
| **Tutti in memoria** | Switch istantaneo | RAM elevata |
| **Lazy: scarica tab inattivi** | RAM bassa | Latenza allo switch |
| **LRU cache (max 3 in memoria)** | Bilanciato | Complessità media |

**Raccomandazione:** Iniziare con "tutti in memoria" e aggiungere un limite configurabile in seguito.

### 🟡 D5: Drag & drop con tabs — replace o nuovo tab?

Quando l'utente droppa un file sul viewer:
- **Opzione A:** Sostituisce il tab corrente
- **Opzione B:** Apre un nuovo tab
- **Opzione C:** Chiedi all'utente (dialog)

**Raccomandazione:** Opzione A (replace tab corrente) + Shift-drop per nuovo tab. Naturale e senza attrito.

## 7. Rischi e punti d'attenzione

- **pdfjs-dist `PDFDocumentProxy` non è clonabile**: ogni tab deve creare la propria istanza da `ArrayBuffer`
- **Cache bitmap**: `clearBitmapCache()` azzera tutto. Serve `invalidateTabCache(tabId)` selettiva
- **Perdita di memoria**: `pdf.cleanup()` / `pdf.destroy()` alla chiusura del tab
- **TOC panel**: attualmente riceve `pdf!` come prop. Con i tabs, riceve `activeTab.pdf`
- **URL routing**: valutare se riflettere il tab attivo nell'URL (`?tab=2`) — skip per ora
